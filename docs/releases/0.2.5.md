**Pi 1.3.0 compatibility for the community Python SDK, with expanded wire metadata and unchanged RPC command behavior.**

## Upgrade notes

Pi **1.3.0** replaces 1.0.0 as the tested baseline. Users of `strict_version=True` must align their separately installed Pi runtime with 1.3.0 when upgrading the SDK. The minimum remains **0.85.1**; other recognized versions at or above the minimum are allowed by default with `compatibility="untested"` ([#100](https://github.com/cheenulabs/pi-agent-python-sdk/pull/100)).

Code explicitly annotating settlement events as `EmptySessionEvent` should now use `AgentSettledEvent` from `pi_agent.types`. Its `aborted` field is optional for older runtimes; runtime event dictionaries are unchanged.

```python
# Before
from pi_agent.types import EmptySessionEvent

settled: EmptySessionEvent = {"type": "agent_settled"}
```

```python
# After
from pi_agent.types import AgentSettledEvent

settled: AgentSettledEvent = {"type": "agent_settled"}
```

[Compatibility policy →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.5/docs/compatibility.md)

## Expanded wire metadata

Typed dictionaries now describe optional message/tool durations, malformed tool arguments, per-thinking-level sampling overrides, and settlement abort metadata. Unknown fields remain accessible. The SDK preserves this metadata without implementing Pi's timing, argument validation, or sampling behavior.

[Wire annotations →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.5/docs/api.md#events-and-wire-types)

## Pi-owned tool and provider changes

The SDK recognizes Pi's `--no-mcp` flag through `extra_args=["--no-mcp"]`. Pi 1.3.0 keeps MCP tools when a `--tools` allowlist has no `mcp__` entry; use the explicit flag to disable MCP. Azure users must change the Pi provider ID from `azure-openai-responses` to `azure`. Pi continues to own authentication, model execution, tools, and sessions; upgrading this Python package does not upgrade Pi.

[Protocol inventory →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.5/docs/discovery.md#pi-130-update) · [RPC guide →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.5/docs/rpc.md)

## Requirements and installation

| Requirement | Version |
| --- | --- |
| Python | **3.11+** |
| Pi protocol baseline (tested) | **1.3.0** |
| Pi protocol minimum | **0.85.1** |
| Node.js for Pi 1.3.0 | **22.19.0+** |

```sh
python -m pip install --upgrade pi-agent-python-sdk==0.2.5
npm install -g @earendil-works/pi-coding-agent@1.3.0
```

Import the Python package as `pi_agent`. Configure Pi separately with your provider and model.
