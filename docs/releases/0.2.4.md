**Pi 1.0.0 compatibility for the community Python SDK, with expanded wire annotations and no breaking Python API changes.**

## Tested Pi 1.0.0 baseline

Pi **1.0.0** now reports `compatibility="tested"` and is accepted by `strict_version=True`. The minimum remains **0.85.1**. Other recognized versions at or above the minimum remain allowed by default but report `compatibility="untested"`. This changes the tested baseline from 0.87.0 in SDK 0.2.3; strict-version users should align their separately installed Pi runtime with 1.0.0 when upgrading ([#93](https://github.com/cheenulabs/pi-agent-python-sdk/pull/93)).

[Compatibility policy →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.4/docs/compatibility.md)

## Input dispositions

Pi 1.0.0 reports whether input was handled, queued or started. Python `prompt()`, `steer()` and `follow_up()` continue to return `None` after checked acknowledgement. Use `request()` to read `data.disposition`; use `run()` or streaming for completed results. An acknowledgement is not a settled-run result.

[Command API →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.4/docs/api.md#all-33-rpc-commands)

## Expanded wire annotations

Typed dictionaries now describe assistant thinking levels, nested tool-call records, parent tool-call IDs and optional model type. Existing raw payloads and unknown fields remain accessible, and optional annotations preserve compatibility with older supported runtimes. Pi continues to own authentication, model execution, tools and sessions.

[Protocol inventory →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.4/docs/discovery.md) · [RPC guide →](https://github.com/cheenulabs/pi-agent-python-sdk/blob/v0.2.4/docs/rpc.md)

## Requirements and installation

| Requirement | Version |
| --- | --- |
| Python | **3.11+** |
| Pi protocol baseline (tested) | **1.0.0** |
| Pi protocol minimum | **0.85.1** |
| Node.js for Pi 1.0.0 | **22.19.0+** |

```sh
python -m pip install --upgrade pi-agent-python-sdk==0.2.4
```

Import the package as `pi_agent`. Pi is installed and configured separately.
